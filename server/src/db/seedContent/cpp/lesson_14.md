# Урок 14. Деванагарі: чому це стрес-тест

## Момент, коли латиниця перестає допомагати

Шість уроків ми працювали з текстом, і все було відносно просто: «Привіт» — це 6 символів, 12 байтів у UTF-8, шукай підрядок, готово. Тепер у нас деванагарі. І ось тут починається справжній Unicode. Один «знак» на екрані — це ланцюжок із 2–4 код-пойнтів, які треба правильно склеїти. Один голосний знак може стояти зліва, справа, зверху, знизу від приголосної — і змінювати її форму. Літери з'єднуються в лігатури, які виглядають як єдиний гліф, але технічно це три окремі символи.

Це не просто «інша мова» — це інша модель тексту. Якщо ти це опануєш, тобі буде байдуже, якою мовою писати наступний проект. Якщо ні — кожне повідомлення в Telegram з емодзі-прапором, кожне японське ім'я, кожен арабський напис — біль.

## Код-пойнти, склади, лігатури: три рівні

Давай розберемо конкретний приклад. Слово `क्ष` (яке виглядає як один знак, «кша»). У коді воно виглядає так:

```
"क्ष"
```

Але технічно це три Unicode-код-пойнти:
- `U+0915` (क) — приголосна «ка»
- `U+094D` (्) — знак «вірáма», який каже «не вимовляй як окремий склад»
- `U+0937` (ष) — приголосна «ша»

Ці три символи рендерер повинен правильно склеїти в один гліф «кша» з характерною формою, де видно «ка» зверху і «ша» знизу, без вертикальної риски між ними. Кількість «символів» = 3, але візуально це одне ціле. У деяких мовах програмування при роботі з текстом вважається «1 знак = 1 гліф» (наприклад, у Python з `grapheme clusters`), у C++ зі `std::string` — `1 знак = 1 байт`, і про графи нічого невідомо.

## Код уроку

Цей урок дає застосунку новий постійний файл — `src/text/Devanagari.h`. Досі ми вміли рахувати байти й код-пойнти; тепер навчимося рахувати те, що людина назве знаком, і безпечно різати слово. Без цього неможливо ані показати слово в картці з обрізанням, ані вирівняти колонку в списку, ані порахувати «довжину» слова для статистики.

```cpp
// src/text/Devanagari.h
// Розбір рядка деванагарі на те, з чого він насправді складається.
// Заголовок. Сам по собі не збирається — його підключають інші файли.
#pragma once

#include <string>
#include <vector>

namespace devanagari {

// ===== UTF-8 -> код-пойнти =====
// Довжина послідовності записана в старших бітах першого байта:
//   0xxxxxxx -> 1 байт, 110xxxxx -> 2, 1110xxxx -> 3, 11110xxx -> 4.
inline std::vector<char32_t> toCodePoints(const std::string& s) {
    std::vector<char32_t> out;
    size_t i = 0;
    while (i < s.size()) {
        unsigned char b = static_cast<unsigned char>(s[i]);
        int len;
        char32_t cp;
        if      ((b & 0x80) == 0x00) { len = 1; cp = b; }
        else if ((b & 0xE0) == 0xC0) { len = 2; cp = b & 0x1F; }
        else if ((b & 0xF0) == 0xE0) { len = 3; cp = b & 0x0F; }
        else if ((b & 0xF8) == 0xF0) { len = 4; cp = b & 0x07; }
        else { ++i; continue; }              // биті дані — пропускаємо байт

        if (i + static_cast<size_t>(len) > s.size()) break;   // обірваний хвіст
        for (int k = 1; k < len; ++k) {
            cp = (cp << 6) | (static_cast<unsigned char>(s[i + k]) & 0x3F);
        }
        out.push_back(cp);
        i += static_cast<size_t>(len);
    }
    return out;
}

// ===== Скільки байтів займає код-пойнт в UTF-8 =====
inline int utf8Length(char32_t cp) {
    if (cp < 0x80)    return 1;
    if (cp < 0x800)   return 2;
    if (cp < 0x10000) return 3;
    return 4;
}

// ===== Вірама: знак "у попередньої приголосної немає голосного" =====
inline bool isVirama(char32_t cp) { return cp == 0x094D; }

// ===== Знаки, які не стоять самі по собі =====
// Матри (голосні при приголосній), анусвара, чандрабінду, вісарга,
// нукта, вірама, ведичні наголоси. Усі вони чіпляються до попередньої букви.
inline bool isCombining(char32_t cp) {
    return (cp >= 0x0900 && cp <= 0x0903)   // чандрабінду, анусвара, вісарга
        || (cp == 0x093A) || (cp == 0x093B)
        || (cp == 0x093C)                    // нукта
        || (cp >= 0x093E && cp <= 0x094F)    // матри й вірама
        || (cp >= 0x0951 && cp <= 0x0957)    // наголоси
        || (cp >= 0x0962 && cp <= 0x0963);
}

// ===== Розбиття на кластери =====
// Кластер — те, що людина сприймає як один знак: приголосна з усіма
// своїми матрами, а якщо між приголосними стоїть вірама, вони зливаються
// в лігатуру й лишаються одним кластером.
//
// УВАГА: це спрощене правило для деванагарі, а не повний алгоритм
// grapheme clusters зі стандарту Unicode. Для решти писемностей світу
// потрібна ICU; тут нам вистачає рівно цього.
inline std::vector<std::string> toClusters(const std::string& s) {
    std::vector<std::string> out;
    auto cps = toCodePoints(s);

    std::string current;
    bool afterVirama = false;

    for (size_t i = 0; i < cps.size(); ++i) {
        char32_t cp = cps[i];
        bool startsNew = !current.empty() && !isCombining(cp) && !afterVirama;

        if (startsNew) {
            out.push_back(current);
            current.clear();
        }

        // дописуємо код-пойнт назад у UTF-8
        int len = utf8Length(cp);
        if (len == 1) {
            current += static_cast<char>(cp);
        } else if (len == 2) {
            current += static_cast<char>(0xC0 | (cp >> 6));
            current += static_cast<char>(0x80 | (cp & 0x3F));
        } else if (len == 3) {
            current += static_cast<char>(0xE0 | (cp >> 12));
            current += static_cast<char>(0x80 | ((cp >> 6) & 0x3F));
            current += static_cast<char>(0x80 | (cp & 0x3F));
        } else {
            current += static_cast<char>(0xF0 | (cp >> 18));
            current += static_cast<char>(0x80 | ((cp >> 12) & 0x3F));
            current += static_cast<char>(0x80 | ((cp >> 6) & 0x3F));
            current += static_cast<char>(0x80 | (cp & 0x3F));
        }

        afterVirama = isVirama(cp);
    }
    if (!current.empty()) out.push_back(current);
    return out;
}

// ===== Безпечне обрізання: рівно n кластерів, а не n байтів =====
inline std::string firstClusters(const std::string& s, size_t n) {
    std::string out;
    for (const auto& c : toClusters(s)) {
        if (n-- == 0) break;
        out += c;
    }
    return out;
}

}  // namespace devanagari
```

```cpp
// exercises/ex14_devanagari.cpp
#include <iostream>
#include <iomanip>
#include "../src/domain/Word.h"
#include "../src/text/Devanagari.h"

void analyse(const std::string& text) {
    auto cps      = devanagari::toCodePoints(text);
    auto clusters = devanagari::toClusters(text);

    std::cout << text << "\n";
    std::cout << "  байтів:      " << text.size() << "\n";
    std::cout << "  код-пойнтів: " << cps.size() << "\n";
    std::cout << "  знаків:      " << clusters.size() << "\n";
    // ... далі друк розкладу по U+XXXX і самих кластерів
}

int main() {
    analyse("नमस्ते");   // намасте
    analyse("धर्म");     // дгарма
    analyse("क्ष");      // кша — одна лігатура з двох приголосних
    analyse("योग");     // йоґа

    std::string word = "नमस्ते";
    std::cout << "substr(0, 9):       " << word.substr(0, 9)  << "\n";
    std::cout << "substr(0, 10):      " << word.substr(0, 10) << "\n";
    std::cout << "firstClusters(, 2): " << devanagari::firstClusters(word, 2) << "\n";
    return 0;
```

Ось воно, головне число уроку: для слова `नमस्ते` — **18 байтів, 6 код-пойнтів, 3 знаки**. Три різні відповіді на питання «яка довжина цього слова», і всі три правильні, просто на різні питання. Для латиниці всі три збіглися б і питання б не виникло взагалі.

Подивись на кожне слово окремо, це того варте.

`नमस्ते` — шість код-пойнтів злипаються в три знаки. Перші два, `न` і `म`, самостійні. А далі йде `स` + ВІРАМА + `त` + матра Е: вірама склеїла дві приголосні в лігатуру `स्त`, а матра Е повісилася зверху — і все це разом дало один знак `स्ते`. Одна ітерація циклу, чотири код-пойнти.

`धर्म` — той самий випадок, що ми розбирали в уроці 6, тепер із точною відповіддю: **два знаки**, а не три. `र` разом із вірамою не малюється окремо взагалі — вона стає гачком над `म`.

`क्ष` — крайній випадок: три код-пойнти, **один** знак. Дві різні приголосні, `ка` і `ретрофлексна ша`, склеєні вірамою в лігатуру, яка виглядає як окрема буква і навіть має власну назву. Санскритологи сперечаються, чи вважати її окремою літерою алфавіту; Unicode такої літери не має взагалі.

`योग` — а тут навпаки: три код-пойнти, два знаки, і матра О (`ो`) малюється **з обох боків** приголосної одночасно — частина зліва, частина зверху. У пам'яті вона стоїть після `य`, на екрані — навколо неї. Ось чому «порядок символів у рядку» і «порядок знаків на екрані» в деванагарі — це різні речі.

Друга частина показує, чим це загрожує практично. `substr(0, 9)` випадково спрацював — межа дев'ятого байта збіглася з межею символу. `substr(0, 10)` розірвав символ навпіл, і консоль намалювала знак-замінник. А `firstClusters(word, 2)` дав рівно два перші знаки й не може зламатися в принципі, бо ріже по межах, які сам і порахував.

Розберемо, що тут відбувається.

**Декодування UTF-8 — це п'ять рядків, а не бібліотека.** Подивись на `toCodePoints`: усе, що потрібно, — прочитати старші біти першого байта й дізнатися довжину послідовності:

- `0xxxxxxx` — 1 байт (ASCII)
- `110xxxxx` — 2 байти (кирилиця)
- `1110xxxx` — 3 байти (це наші деванагарі)
- `11110xxx` — 4 байти (емодзі, рідкісні ієрогліфи)

Далі береш молодші біти першого байта, по шість біт із кожного наступного, зсуваєш і склеюєш. Маска `0x3F` — це `00111111`, вона відрізає ті самі два біти `10`, з яких починається кожен байт-продовження. Саме тому лічильник код-пойнтів з уроку 6 працював: він рахував байти, які **не** починаються з `10`.

**`toClusters` — це вже не декодування, а правило писемності.** Тут немає нічого від Unicode-стандарту як формату: є знання того, як влаштована деванагарі. Комбінуючий знак приєднується до попереднього кластера; після вірами наступна приголосна теж лишається в тому самому кластері. Два правила, десять рядків коду — і ми отримали відповідь, якої не дає жоден метод `std::string`.

**Але чесно про межі цього коду.** Наш `toClusters` знає рівно деванагарі й нічого більше. Для тамільської, бенгальської, кхмерської, тайської правила інші; для емодзі з модифікаторами кольору шкіри — треті; для корейського хангилю — четверті. Повний алгоритм називається **Unicode Text Segmentation** (додаток UAX #29), він займає десятки сторінок, і писати його самому не варто ніколи. У проєкті, який працює з довільними мовами, беруть ICU (`ubrk_open` з `UBRK_CHARACTER`) або Qt (`QTextBoundaryFinder`). Ми пишемо своє тільки тому, що наш застосунок за визначенням працює з однією писемністю — і тому, що інакше ти б не побачив, що саме ховається за викликом бібліотечної функції.

**Нормалізація** — одна з найболючіших тем Unicode. Той самий візуальний символ може мати кілька представлень. «é» — це або один код-пойнт `U+00E9`, або два: `U+0065` (e) + `U+0301` (комбінуючий наголос). Якщо не нормалізувати — порівняння рядків «працює не так, як очікувалося». У нашому SAMSKRTA це критично: якщо користувач введе «धर्म» у преформованій формі, а в базі воно зберігається розібраним, програма його не знайде. Qt має метод `QString::normalized()`, ICU — функції `unorm2_normalize`. Стандартна бібліотека C++ до C++20 — на жаль, ні.

**Лігатури** — окрема тема. У деванагарі деякі комбінації приголосних мають особливу форму (тільки `क्ष`, `त्र`, `ज्ञ` з найпоширеніших). У простому текстовому файлі вони виглядають як кілька символів, але рендерер повинен знати, що це «лігатура», і малювати спеціальну форму. Qt і більшість рендерерів (HarfBuzz, DirectWrite) це вміють. `std::cout` у консолі — залежить від шрифту, в Linux зазвичай через Fontconfig + Pango, у Windows — через DirectWrite.

**Комбінуючі голосні** — ще одна особливість. У деванагарі голосна «e» (े) після приголосної — це окремий символ, який ставиться зліва від приголосної. У тексті: `के`. В Unicode: `U+0915` + `U+0947`. Байт у UTF-8: 6 байт. Символів: 2. Гліфів: 1 (бо голосна «прилипає» до приголосної). Це класичний приклад того, чому просте «count символів» не працює.

## Де це реально використовується

**HarfBuzz** — бібліотека для OpenType-шейпінгу, яку використовують Qt, Chrome, Firefox, Android, iOS, Unreal Engine. Саме вона перетворює послідовність Unicode-код-пойнтів у правильні гліфи із замінами лігатур, перетвореннями форм, позиціонуванням діакритики. Без неї деванагарі, арабська, тайська — каша. З нею — нормальний текст.

**ICU (International Components for Unicode)** — «швейцарський ніж» Unicode. Нормалізація, транслітерація, робота з календарями, часові пояси, числа, валюта, локалі — все, що стосується інтернаціоналізації. Qt використовує ICU під капотом у багатьох місцях, хоча має й свої реалізації. Серйозні проекти з Unicode (Evernote, Notion, Lingvanex) тримають ICU як основну залежність.

**Google Noto Fonts** — сімейство шрифтів від Google, яке покриває всі Unicode-символи. Без шрифту, навіть якщо код правильний, ти побачиш квадратики замість літер. «Noto» означає «no tofu» — жарт про квадратики-тофу, які з'являються, коли шрифт не має потрібного символу. У нашому SAMSKRTA ми використовуємо Noto Sans Devanagari для деванагарі.

**Класична помилка з емодзі-прапорами**: прапор України в емодзі — це два код-пойнти: «U» (регіональний індикатор U) + «A» (регіональний індикатор A). Україна = UA. Японія = JP. Китай = CN. Росія = RU. Це спеціальний механізм Unicode, де дві «регіональні літери» склеюються в прапор. Якщо твій код випадково розділить ці два символи — замість 🇺🇦 буде «U» + «A» окремо. Таке буває в старих JS-додатках, які неправильно обробляють сурогатні пари в UTF-16.

**Аналогія з конструктором Lego**: уяви, що кожен Unicode-код-пойнт — це цеглинка Lego. У латиниці один цеглинка = одна літера. Просто. У деванагарі один гліф = три-чотири цеглинки, склеєні в певний спосіб. Тобі потрібна інструкція, щоб знати, як їх склеїти. Ця інструкція — алгоритм шейпінгу (HarfBuzz, ICU, DirectWrite). Без інструкції у тебе просто купа цеглинок, з якими нічого не зробиш.

## Куди це веде далі

**Замість `std::string` для деванагарі** — `QString` (Qt) — найпростіший варіант. Всередині UTF-16, але API ховає це від тебе. Є `normalized()`, є правильне порівняння, є підтримка скриптів.

**Замість ручної нормалізації** — ICU (`unorm2_normalize`) або Qt (`QString::normalized`).

**Замість свого шейпінгу** — підключити бібліотеку HarfBuzz (Qt уже це робить за тебе). У Qt 6 є `QTextLayout`, який інтегрується з HarfBuzz і дає правильний рендеринг деванагарі.

**Для тестування** — Python бібліотеки: `grapheme` (рахує графеми), `unicodedata` (нормалізація), `regex` з підтримкою Unicode. Можна написати тести на Python, які перевірять, як поводитиметься твоя C++ програма.
