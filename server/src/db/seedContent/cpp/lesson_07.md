# Урок 7. Вікно на екрані: Qt, перший застосунок

## Після шести уроків без вікон — заслужене

Шість уроків ми провели в консолі. Чорний екран, білий текст, набір тексту на клавіатурі. Для навчання — ідеально: нічого не відволікає від логіки, компілятор лає тебе самим текстом, без візуального шуму. Але ми ж будуємо SAMSKRTA — тренажер для людей, які хочуть бачити деванагарі на екрані, а не в консолі. Тож сьогодні — перше вікно.

Це, напевно, найбільш «магічний» момент усього курсу: ось щойно в тебе був `std::cout`, а ось вже справжнє вікно з кнопкою, яка закриває програму. Магія, правда, зникне, коли ми подивимося, як це влаштовано під капотом. Але відчуття залишиться.

## Вибір бібліотеки GUI: чому Qt

Коли ти починаєш писати GUI на C++, у тебе є вибір:

- **Qt** — найпопулярніший варіант для C++. Крос-платформний, зрілий, з купою всього «в коробці»: віджети, мережа, бази даних, мультимедіа. Той самий, на якому побудований KDE, Telegram Desktop, VLC, OBS Studio.
- **Dear ImGui** — легкий, швидкий, але зовсім інший стиль: «immediate mode», без звичних віджетів. Використовується в ігрових інструментах і дебаг-меню.
- **wxWidgets** — старший брат Qt, трохи простіший, але з меншою спільнотою.
- **GTK** — основа GNOME. Можна з C++, але в спільноті GTK прийнято писати на C, тому C++-обгортки не дуже рівні.
- **FLTK** — мінімалістичний, для навчальних проектів.
- **raw WinAPI / X11 / Cocoa** — коли тобі потрібен абсолютний контроль і готовність до болю.

Ми беремо Qt. Чому:

1. Для нашого проекту (складний текст із деванагарі, кирилиця в інтерфейсі, аудіо, PDF, бази даних) — це найменш болісний варіант.
2. Крос-платформний: той самий код компілюється на Windows, Linux, macOS. Навіть Android та iOS.
3. Власна система рядків (`QString`), яка нормально працює з Unicode з коробки. Не треба думати, скільки байтів у літері.
4. Величезна спільнота. Яка б проблема в тебе не виникла — хтось уже поставив це питання на StackOverflow.

## Встановлення Qt

Найпростіший шлях — **Qt Online Installer** з сайту `qt.io`. Завантажуєш, запускаєш, обираєш версію Qt (для нашого курсу — Qt 6.x), компілятор (MSVC 2022 для Windows, GCC для Linux, Clang для macOS). Все інше за заличенням.

Альтернатива для тих, хто не хоче реєструватися: в Ubuntu `sudo apt install qt6-base-dev qt6-tools-dev qtcreator`. На macOS через Homebrew: `brew install qt`. Головне — щоб версія Qt збігалася в усіх місцях (якщо компілятор шукає Qt 6.7, а в системі Qt 6.5 — буде біль).

**CMake** (ми його вже поставили в уроці 2) вміє знаходи Qt автоматично, але іноді треба підказати шлях: `cmake -DCMAKE_PREFIX_PATH=/шлях/до/Qt/6.7.0/компілятор ..`.

## Код уроку: перше вікно

Це не новий проєкт з нуля — ми дописуємо в той самий `samskrta/`, який завели в уроці 2. `src/main.cpp` більше не консольний: з цього уроку і назавжди він виглядає так. У `CMakeLists.txt` додай (не переписуй, а саме додай) підключення Qt:

```cmake
set(CMAKE_AUTOMOC ON)  # обов'язково для Q_OBJECT, знадобиться з уроку 10
find_package(Qt6 REQUIRED COMPONENTS Widgets)
target_link_libraries(samskrta PRIVATE Qt6::Widgets)
```

Перебудуй: `cmake -B build -S . && cmake --build build`. Тепер `src/main.cpp`:

```cpp
// src/main.cpp — заміняє консольну версію з уроку 2, назавжди
#include <QApplication>
#include <QWidget>
#include <QLabel>
#include <QPushButton>
#include <QVBoxLayout>
#include <QString>

int main(int argc, char* argv[]) {
    QApplication app(argc, argv);   // <-- обов'язково, інакше Qt не працює

    // Створюємо головне вікно
    QWidget window;
    window.setWindowTitle("SAMSKRTA — перше вікно");

    // Створюємо віджети
    QLabel* greeting = new QLabel("Привіт, мандрівнику! Готовий до санскриту?");
    QPushButton* startButton = new QPushButton("Почати");

    // Розміщуємо віджети зверху вниз
    QVBoxLayout* layout = new QVBoxLayout(&window);
    layout->addWidget(greeting);
    layout->addWidget(startButton);

    // Обробник натискання кнопки
    QObject::connect(startButton, &QPushButton::clicked, [&]() {
        greeting->setText("Чудово! Пункт призначення — деванагарі.");
        startButton->setEnabled(false);  // щоб не натискали вдруге
    });

    window.resize(420, 180);
    window.show();   // показати вікно

    return app.exec();   // головний цикл Qt
}
```

Розберемо, що тут відбувається.

**`QApplication app(argc, argv)`** — без цього жоден Qt-проект не запуститься. `QApplication` — це «диспетчерська»: вона тримає зв'язок з операційною системою, читає події від мишки та клавіатури, передає їх віджетам, керує головним циклом. Створюється рівно один раз на початку програми. Уяви її як адміністратора готелю: він не прибирає номери і не готує сніданки, але без нього ніхто не знає, що робити.

**`QWidget window`** — найбазовіший віджет Qt. Усе, що ти бачиш на екрані у Qt-додатку — це `QWidget` або його нащадок: вікно, кнопка, напис, поле вводу, таблиця. Навіть сама головна форма — це `QWidget`. Ієрархія віджетів — це дерево: головне вікно містить лейаути, лейаути містять дочірні віджети, ті — свої.

**`QLabel`, `QPushButton`** — конкретні віджети. `QLabel` показує текст, `QPushButton` — кнопка. Qt має десятки готових віджетів: `QLineEdit` (поле вводу), `QCheckBox` (чекбокс), `QComboBox` (випадний список), `QTableView` (таблиця), `QListView` (список), `QSlider` (повзунок) — і це далеко не все. Ти можеш провести все життя в Qt, не написавши жодного свого віджета.

**`QVBoxLayout`** — «вертикальний контейнер». Кладемо в нього лейбл і кнопку, і вони автоматично вишикуються зверху вниз. Є ще `QHBoxLayout` (горизонтально), `QGridLayout` (таблиця), `QFormLayout` (форми). Лейаути — головний спосіб Qt робити «гарно» без написання координат у пікселях. Ти кажеш «ці віджети мають бути один під одним», Qt сам рахує розміри і переміщує при зміні вікна. Це як сказати «постав тарілки на стіл», а не «поклади першу тарілку в точку (x=10, y=20), а другу в (x=10, y=80)».

**`QObject::connect(startButton, ...)`** — найважливіший рядок у Qt. Це **сигнали і слоти** — механізм, через який віджети спілкуються. «Коли кнопка відправляє сигнал `clicked` (тобто її натиснули), виклич цю лямбду». Qt повністю побудований на цій ідеї: один об'єкт каже «я зробив ось таку подію», інший кажи «я хочу про це знати», і Qt сам викликає потрібний код. Це називається **спостерігач** (observer), і в Qt воно реалізовано елегантніше, ніж у більшості мов. Якщо в тебе колись буде питання «як дізнатися, що користувач натиснув кнопку» — відповідь завжди `connect`.

**`app.exec()`** — головний цикл програми. Це нескінченний цикл, де Qt чекає подій (натискань, руху мишки, таймерів) і роздає їх віджетам. Програма не йде далі, поки цей цикл не завершиться (зазвичай — коли закривається головне вікно). Все, що відбувається у вікні — результат цього циклу.

## Три способи отримати порожній екран замість вікна

**Забути `app.exec()`.** Прибери останній рядок, залиш `return 0;` — і побачиш той самий фокус, що й із забутим `endl` в уроці 1: `window.show()` лише *просить* систему намалювати вікно, а сама відмальовка й обробка кліків відбуваються всередині циклу подій. Без `exec()` цей цикл ніколи не запускається — `main()` одразу повертає керування, і вікно, не встигнувши з'явитися, зникає разом із процесом.

**Створити другу `QApplication`.** Додай у `main()` ще один рядок `QApplication app2(argc, argv);` — застосунок впаде з `QApplication: There should be only one QApplication object` ще до показу будь-чого. Не м'яке попередження, а жорстка заборона на рівні рантайму.

**Створити віджет до `QApplication`.** Поміняй місцями перші два рядки `main()` — і отримаєш падіння або невизначену поведінку залежно від платформи: віджетам потрібна вже існуюча `QApplication` — вона ініціалізує всю інфраструктуру шрифтів і подій, і раніше цього моменту питати Qt «намалюй щось» просто нікому.

## Хто видаляє вікно: інша модель володіння пам'яттю

У наступних уроках знадобляться кнопки й підписи всередині вікна, і код виглядатиме так:

```cpp
QPushButton* button = new QPushButton("Далі", &window);
```

`new` без жодного `delete` — і це не помилка, не забутий витік. Другий аргумент конструктора, `&window`, — це **батько**. Qt поверх звичайної пам'яті C++ вибудовує власне дерево володіння: коли батьківський об'єкт руйнується, він автоматично проходить по всіх своїх дітях і видаляє їх сам, без жодного твого рядка коду. Це не скасовує все, що ти дізнаєшся про `new`/`delete` в уроці 11, — `button` як і раніше звичайний вказівник, `&window` — звичайна адреса, — а додає поверх ще один, чисто бібліотечний договір: «сирий вказівник із батьком — це не витік, а усвідомлена передача відповідальності контейнеру».

## Де все це насправді використовується

**KDE Plasma** — найбільший Qt-проект у світі. Це вся оболонка робочого столу: панель задач, меню «Пуск», файловий менеджер, системні налаштування. Мільйони рядків коду на Qt, і все завдяки тим самим `QWidget`, `QLayout`, `connect`. Коли ти клацаєш по іконці в KDE — спрацьовує сигнал `clicked` на `QPushButton`, який через лейаут підключений до певного слота, який відкриває потрібний додаток.

**Telegram Desktop** — ще один великий Qt-проект. Месенджер із сотнями мільйонів користувачів, написаний на тому самому Qt, на якому ми зараз пишемо наш тренажер. Усе, від списку чатів до відправки стікерів, працює на тих самих механізмах, що й у нашому маленькому віконці.

**OBS Studio** (запис екрану, яким користуються всі стрімери) — теж Qt. У них складний інтерфейс із сценами, джерелами, фільтрами, і все це — дерево `QWidget`-ів.

**Модель «сигнал-слот»** стала настільки популярною, що в C++20 з'явилася бібліотека `std::signals` — спроба стандартизувати те, що Qt робив уже 30 років. У Boost, до ректу, є `boost::signals2` — та сама ідея для тих, хто не хоче тягнути Qt.

**Аналогія з рестораном**: `QApplication` — це адміністратор. `connect` — це запис у книзі скарг: «якщо гість №5 (кнопка) скаже щось (сигнал), передай офіціанту №3 (слот)». `app.exec()` — це зміна ресторану: всі чекають, поки хтось щось замовить, і обробляють замовлення одне за одним. Без адміністратора ніхто не знає, хто що робить. Без головного циклу ніхто нікого не обслуговує. Qt просто формалізував те, як працює будь-який інтерактивний застосунок.

## Куди це веде далі

**Замість Qt Widgets** (наш вибір) — Qt Quick / QML:

```qml
// main.qml — той самий застосунок, але сучасніше
import QtQuick
import QtQuick.Controls

ApplicationWindow {
    width: 420
    height: 180
    title: "SAMSKRTA — перше вікно"
    visible: true

    Column {
        anchors.centerIn: parent
        Label {
            id: greeting
            text: "Привіт, мандрівнику!"
        }
        Button {
            text: "Почати"
            onClicked: {
                greeting.text = "Чудово! Пункт призначення — деванагарі."
                enabled = false
            }
        }
    }
}
```

QML — це декларативний опис інтерфейсу (як JSON або HTML, тільки з логікою на JavaScript). Qt Quick особливо популярний для мобільних і для анімованих інтерфейсів. У цій книзі ми починаємо з Widgets, бо вони простіші для розуміння, а в Part XI переходимо до Quick.

**Замість ручної компіляції** — **Qt Creator** як IDE. Все з коробки: редактор із підказками, вбудований дебагер, профілювальник, дизайнер форм. Для новачка — мабуть, найшвидший старт. Для профі — кому як, хтось любить, хтось ні.

**Замість `QObject::connect`** — лямбди в нових версіях Qt 6:

```cpp
connect(startButton, &QPushButton::clicked, this, [this]() {
    // обробник
});
```

У Qt 5 був жахливий синтаксис з `SLOT()` і `SIGNAL()` макросами, які перевірялися тільки під час виконання. Qt 6 зробив це типобезпечним, як у нашому прикладі. Якщо побачиш старий код з `SLOT(onButtonClicked)` — не лякайся, це той самий механізм, просто написаний інакше.

## Питання для самоперевірки

1. Збери проект із сьогоднішнього коду. Запусти. Натисни кнопку. Що змінилося?
2. Додай у вікно ще одну кнопку «Вийти», яка закриває програму. Підказка: `QApplication::quit()`.
3. Заміни `QVBoxLayout` на `QHBoxLayout`. Як зміниться вікно?
4. Спробуй створити два вікна (два `QWidget show()`). Що відбувається при закритті одного з них? Чому?
5. Знайди в інтернеті Qt-проект із GitHub, який робить щось схоже на наш. Подивись, як там організований код.
