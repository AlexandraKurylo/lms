# Урок 8. Слово як структура даних

## Передмова: дані — це все

Програма без даних — як автомобіль без бензину: форму є, толку мало. Усі наші попередні уроки були про форму: як написати цикл, як зловити вказівник, як відкрити вікно. Сьогодні починається зміст: що саме ми зберігаємо в пам'яті, в якій структурі, як до неї звертаємося.

Для SAMSKRTA центральне поняття — **слово**. Одне слово санскриту. Що ми про нього знаємо? Саме слово в деванагарі (`धर्म`), транслітерація латиницею (`dharma`), переклад українською (`закон, обов'язок, істина`), приклад у реченні, рівень запам'ятовування користувача (за системою інтервального повторення), дата останнього повторення, і ще з десяток полів, які ми додамо в процесі. Як це все зібрати разом? `struct`.

## struct: групуємо пов'язане

```cpp
struct Word {
    std::string devanagari;
    std::string transliteration;
    std::string translation;
    int difficultyLevel;
};
```

Це все. `struct` (структура) — це спосіб сказати компілятору: «ці чотири речі завжди ходять разом, я хочу працювати з ними як з одним цілим». Уяви, що це картка в бібліотечному каталозі: на ній написано автора, назву, рік видання, ISBN. Книги різні, а картка — одного зразка.

У C++ `struct` і `class` — майже одне й те саме (різниця в доступі за замовчуванням: у `struct` — публічний, у `class` — приватний). Ми поки що використовуємо `struct`, бо наші дані — прості контейнери без складної логіки. Коли додадуться правила роботи з даними (методи), перейдемо на `class`.

## Пастка, яку не бачить компілятор

Структуру без власного конструктора можна заповнити просто переліком значень по порядку — це називається **агрегатною ініціалізацією**:

```cpp
Word w{"क", "ka", "к", 2};
```

Зручно, поки полів мало. Але уяви, що `Word` виросла до восьми-десяти рядкових полів, і десь у коді вже стоїть така позиційна ініціалізація. Компілятор перевіряє тільки кількість і сумісність типів аргументів, а не їхній сенс: якщо два поля типу `std::string` випадково переставити місцями в оголошенні структури — стара ініціалізація й далі спокійно збереться, тільки тепер переклад тихо потрапить туди, де мала бути транслітерація. Ні помилки компіляції, ні попередження — просто програма, яка неправильно працює точно там, де хтось один раз переплутав порядок полів.

C++20 дає часткові ліки — **ініціалізацію за іменами полів** (designated initializers), синтаксис, запозичений із C:

```cpp
Word w{
    .devanagari = "क",
    .transliteration = "ka",
    .translation = "к",
    .difficultyLevel = 2,
};
```

Переплутати `.translation` і `.transliteration` місцями фізично не вийде — імена написані прямо біля значень. Єдине обмеження: перелічені поля мусять іти в тому самому порядку, в якому вони оголошені в структурі.

## Код уроку

Це `src/domain/Word.h` — файл, що з'явиться в нашому проєкті `samskrta/` і більше не переозначається в жодному наступному уроці. Все, що працює зі словами далі в курсі (синглтон `Database` в уроці 9, `WordCard` в уроці 10, пам'ять в уроці 11, пошук в уроці 15, збереження в уроці 16), підключає саме цей файл рядком `#include "../domain/Word.h"`.

Зверни увагу на дві речі в шапці, яких у попередніх файлах не було — вони обидві потрібні саме тому, що це **заголовок**, а не програма.

`#pragma once` — вказівка компілятору «якщо цей файл уже підключали в цій одиниці трансляції, другий раз не читай». Без неї станеться ось що: урок 9 напише `Database.h`, який підключає `Word.h`, а урок 16 напише `WordRepository.h`, який теж підключає `Word.h`. Щойно якийсь `.cpp` підключить обидва — компілятор двічі прочитає визначення `struct Word` і зупиниться з помилкою «структура вже визначена». Історично для цього писали три рядки з `#ifndef WORD_H`; `#pragma once` робить те саме одним, і його розуміють усі сучасні компілятори.

`inline` перед функціями — слово, яке тут означає зовсім не те, про що можна подумати. Воно не просить компілятор «вставити тіло функції на місце виклику» (це він і так вирішує сам). Воно каже лінкеру: «це визначення може зустрітися в кількох об'єктних файлах, це нормально, візьми будь-яке». Без `inline` кожен `.cpp`, що підключив `Word.h`, отримає власну копію `printWord`, і на етапі лінкування ти побачиш `error LNK2005: printWord already defined`. Правило просте: **функція, тіло якої лежить у заголовку, мусить бути `inline`** (методи, написані прямо в тілі класу, стають такими автоматично — тому в `Database` з наступного уроку цього слова не буде).

```cpp
// src/domain/Word.h
// Заголовок. Сам по собі не збирається — його підключають інші файли.
#pragma once

#include <iostream>
#include <string>
#include <vector>
#include <algorithm>
#include <optional>

// ===== Наша головна структура даних =====
struct Word {
    int id;                       // призначає Database при додаванні, 0 = ще не збережене
    std::string devanagari;       // "धर्म"
    std::string transliteration;  // "dharma"
    std::string translation;      // "закон, обов'язок"
    int difficultyLevel;         // 1..5
    int timesReviewed;           // скільки разів користувач бачив це слово
    bool isKnown;                // чи вивчене

    // Конструктор за замовчуванням
    Word()
        : id(0),
          devanagari(""),
          transliteration(""),
          translation(""),
          difficultyLevel(1),
          timesReviewed(0),
          isKnown(false) {}

    // Зручний конструктор
    Word(std::string dev, std::string tr, std::string t, int diff = 1)
        : id(0),
          devanagari(std::move(dev)),
          transliteration(std::move(tr)),
          translation(std::move(t)),
          difficultyLevel(diff),
          timesReviewed(0),
          isKnown(false) {}
};

// ===== Функції, що працюють з Word =====

// Друк одного слова
inline void printWord(const Word& w) {
    std::cout << w.devanagari << " (" << w.transliteration << ") — "
              << w.translation << " [рівень " << w.difficultyLevel << "]";
    if (w.isKnown) std::cout << "  вивчене";
    std::cout << "\n";
}

// Пошук слова за транслітерацією (повертаємо індекс, або "не знайдено")
inline std::optional<size_t> findByTranslit(const std::vector<Word>& dict,
                                            const std::string& query) {
    for (size_t i = 0; i < dict.size(); ++i) {
        if (dict[i].transliteration == query) return i;
    }
    return std::nullopt;
}

// Позначити слово як вивчене
inline void markAsKnown(Word& w) {
    w.isKnown = true;
    std::cout << "Слово \"" << w.devanagari << "\" позначено як вивчене.\n";
}

// Сортування словника за рівнем складності
inline std::vector<Word> sortByDifficulty(const std::vector<Word>& dict) {
    auto copy = dict;  // копія, бо вихідний порядок не змінюємо
    std::sort(copy.begin(), copy.end(),
              [](const Word& a, const Word& b) {
                  return a.difficultyLevel < b.difficultyLevel;
              });
    return copy;
}

```

Тут файл і закінчується — жодного `main` у заголовку немає й бути не може. Заголовок описує, **що таке слово**; запускати його ніде. Щоб побачити структуру в дії, поруч створюємо вправу `exercises/ex08_word.cpp`, і ось у ній `main` уже є:

```cpp
// exercises/ex08_word.cpp
// Демонстрація структури Word із src/domain/Word.h.
// Збери разом із проєктом: cmake --build build
// Запусти:                 ./build/ex08_word

#include "../src/domain/Word.h"

int main() {
    // Створюємо словник із кількох слів
    std::vector<Word> dictionary = {
        Word("धर्म", "dharma", "закон, обов'язок", 2),
        Word("सत्य", "satya", "істина", 1),
        Word("अहिंसा", "ahimsa", "ненасильство", 4),
        Word("कर्म", "karma", "дія, вчинок", 3),
    };

    std::cout << "=== Початковий словник ===\n";
    for (const auto& w : dictionary) {
        printWord(w);
    }
    std::cout << "\n";

    // Шукаємо слово
    std::cout << "Шукаємо 'satya': ";
    auto found = findByTranslit(dictionary, "satya");
    if (found.has_value()) {
        printWord(dictionary[*found]);
        markAsKnown(dictionary[*found]);
    } else {
        std::cout << "не знайдено\n";
    }
    std::cout << "\n";

    // Шукаємо те, чого немає
    std::cout << "Шукаємо 'moksha': ";
    auto missing = findByTranslit(dictionary, "moksha");
    std::cout << (missing.has_value() ? "знайдено" : "не знайдено") << "\n\n";

    // Сортуємо
    std::cout << "=== Словник за складністю ===\n";
    for (const auto& w : sortByDifficulty(dictionary)) {
        printWord(w);
    }

    return 0;
}
```

Рядок у `CMakeLists.txt`:

```cmake
add_executable(ex08_word  exercises/ex08_word.cpp)
```

Заголовок у `add_executable` не згадується взагалі, і це не помилка: компілятор знайде його сам, бо `ex08_word.cpp` каже `#include`. У списку джерел перелічують тільки `.cpp` — заголовки підтягуються автоматично.

Вивід:

```
=== Початковий словник ===
धर्म (dharma) — закон, обов'язок [рівень 2]
सत्य (satya) — істина [рівень 1]
अहिंसा (ahimsa) — ненасильство [рівень 4]
कर्म (karma) — дія, вчинок [рівень 3]

Шукаємо 'satya': सत्य (satya) — істина [рівень 1]
Слово "सत्य" позначено як вивчене.

Шукаємо 'moksha': не знайдено

=== Словник за складністю ===
सत्य (satya) — істина [рівень 1]  вивчене
धर्म (dharma) — закон, обов'язок [рівень 2]
कर्म (karma) — дія, вчинок [рівень 3]
अहिंसा (ahimsa) — ненасильство [рівень 4]
```

Порівняй перший і останній блоки виводу — і згадай урок 4, де той самий словник лежав у трьох паралельних масивах. Там, щоб дізнатися рівень слова, треба було знати його індекс і не переплутати масиви; щоб відсортувати за складністю, довелося б переставляти елементи **в трьох масивах одночасно**, не збившись. Тут сортування — це три рядки з однією лямбдою, і переплутати нічого фізично неможливо, бо поля подорожують разом зі словом. Ось за що платять структурою.

Розберемо, що тут відбувається.

**Конструктор з ініціалізацією через `: ...`** — список ініціалізації. Замість присвоювання в тілі конструктора, ми відразу кажемо «ось такі початкові значення». Це швидше (один крок замість двох) і обов'язково для константних полів і полів-посилань. Для складних типів на кшталт `std::string` різниця відчутна: інакше спочатку створюється порожній рядок, а потім йому присвоюється нове значення, а з `std::move` — одразу переміщається готовий.

**`std::move(dev)`** — «перемісти, а не копіюй». Ми детально розбиратимемо це в уроці 13, поки що запам'ятай: коли ти передаєш щось у конструктор, який більше не знадобиться, використовуй `std::move`, щоб не витрачати час на копіювання. Це як переїхати в нову квартиру: забрати свої речі (move) швидше, ніж купити нові такі самі (copy).

**`const Word&` у функціях** — пам'ятаєш з уроку 5? Параметр-посилання, обіцянка не змінювати. `printWord` нічого не змінює, тому `const&`. А ось `markAsKnown` змінює — там просто `Word&` без `const`.

**`std::optional<size_t>`** — значення, якого може не бути. Старий стиль — повертати `-1` як ознаку «не знайдено» (працює, але магічне число і не працює з `size_t`, яке беззнакове). Новий стиль — `std::optional<T>`. Має значення `.has_value()`, якщо є, або `.value()` для отримання. Це набагато безпечніше, бо компілятор змусить тебе перевірити, чи є значення, перед тим як його використовувати.

**Лямбда в `std::sort`** — `[](const Word& a, const Word& b) { return a.difficultyLevel < b.difficultyLevel; }`. Безіменна функція, написана на місці. Потрібна тут, бо `std::sort` вимагає «функцію порівняння двох елементів», і писати для цього окрему функцію — забагато. Лямбда каже: «ось тобі порівняння: чим менше difficultyLevel, тим раніше в списку».

**Range-based `for` з `const auto&`** — знову шаблон з уроку 5: перебір без копіювання, без зміни. `for (const auto& w : dictionary)` — ідиоматичний спосіб «пройтися по всьому вектору».

## Де це вже використовується

**Кожен серйозний C++-проект починається з визначення своїх головних типів даних.** У Qt це `QString`, `QList`, `QHash`. У Boost — `boost::variant`, `boost::any`. У Unreal Engine — `FVector`, `FRotator`, `AActor`. Кожна бібліотека вирішує, як їй зручно представляти «сутність». Для нашого SAMSKRTA головна сутність — `Word`, і вона визначена в першому ж рядку моделі даних.

**Pod (Plain Old Data)** — термін для простих структур, які не мають віртуальних функцій і складних конструкторів. У C++20 з'явився спеціальний синтаксис для них — `struct Word { ... }` без вказівки — але в цілому `struct` залишається способом згрупувати пов'язані дані. Коли в тебе є `struct Point { double x, y; }` — це POD. Коли є `class Database` із власним конструктором, деструктором, методами, віртуальними функціями — це вже не POD, і з ним інакше поводяться компілятор, контейнери, деякі алгоритми.

**`std::optional` з C++17** — одна з тих речей, які після першого використання здаються настільки очевидними, що дивуєшся, як без них жили. У старому C++ повертали «магічне -1», або вказівник `nullptr`, або bool-прапорець + параметр за посиланням. Все це було незручно. `std::optional` — це «коробка, в якій може лежати значення, а може бути порожня». Зрозуміло, типобезпечно, без магічних чисел. У Qt є аналог — `QOptional`, у Rust є `Option<T>` (там він називається `Option` і використовується в кожному другому рядку), у Haskell — `Maybe`. Ідея універсальна.

**Аналогія з паспортом**: `struct Word` — це паспорт. У кожного паспорта одні й ті самі поля: ім'я, прізвище, дата народження, фотографія. Але кожен конкретний екземпляр заповнений своїми даними. Ти можеш зробити функцію `printPassport(passport)`, яка надрукує все, незалежно від того, чи це паспорт Івана, чи Марії. Структура — це шаблон, екземпляр — конкретний документ. Конструктор — це «приймальня, де тобі видають чистий бланк для заповнення».

## Куди це веде далі

**Замість `struct Word` з простими полями** — `class Word` з методами:

```cpp
class Word {
    std::string devanagari;
    int difficultyLevel;
public:
    bool isHard() const { return difficultyLevel >= 4; }
    void markReviewed() { /* складна логіка */ }
};
```

Різниця — у `class` можна сховати деталі (`private`) і залишити тільки публічний інтерфейс. Це називається **інкапсуляція** — обмеження доступу до внутрішніх деталей. Поки що наші дані прості, тому `struct` вистачає. Коли додадуться правила («рівень складності не може бути 0», «поле перекладу не може бути порожнім»), перейдемо на `class` із `private` полями і перевірками.

**Замість простого `std::string` для деванагарі** — `QString` (Qt) або щось із підтримкою нормалізації Unicode (ICU). Просте `std::string` зберігає байти, і деякі деванагарі-літери можуть мати два різних представлення в пам'яті (нормалізоване і ні). Для серйозного проекту з Unicode — це проблема, і її вирішують спеціальні бібліотеки.

**Замість `std::vector<Word>`** для словника — може, `std::unordered_map<std::string, Word>` (хеш-таблиця за транслітерацією):

```cpp
std::unordered_map<std::string, Word> dictByTranslit;
dictByTranslit["dharma"] = Word("धर्म", "dharma", "закон");
// Пошук: dictByTranslit.find("dharma") — за O(1) замість O(n)
```

Поки що словник маленький, і лінійний пошук у `vector` непомітний. Коли слів стане 10 000, різниця буде відчутна. Це тема уроку 15.
