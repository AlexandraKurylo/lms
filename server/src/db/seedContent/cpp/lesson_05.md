# Урок 5. Вказівники, масиви, посилання

## Чому всі бояться вказівників

Якщо ти читав форуми, де скаржаться на C++, то бачив ці слова: «вказівники — це найстрашніше», «поки не зрозумієш вказівники, далі можеш не читати», «вказівники зламали мені життя». Це перебільшення, якщо чесно. Вказівник — це просто число. Число, яке зберігає адресу комірки в пам'яті. Нічого містичного.

Уся страшна репутація — від того, що з цим числом можна натворити справ, якщо не розумієш, що робиш. А є й інша причина розібратися з вказівниками саме зараз: через пару уроків у нас з'являться класи, спадкування, поліморфізм. Це виглядатиме як окремий всесвіт з власним синтаксисом. Але це ілюзія. Усередині — ті самі адреси, тільки акуратно упаковані компілятором. Щоб не відчувалося як магія, розберемо один раз і начисто.

## Вказівник на пальцях

Уяви будинок і папірець з його поштовою адресою. Папірець — не будинок: його можна покласти в кишеню, скопіювати десять разів, передати сусідові. Але якщо прийти за цією адресою і пофарбувати двері — будинок за справжньою адресою стане іншого кольору, скільки б копій папірця не валялося по місту. Вказівник — це папірець з адресою. Змінна — будинок. Адреса — не міська, а адреса комірки в пам'яті.

## Код уроку

Третя вправа в дереві проєкту — `exercises/ex05_pointers.cpp`, і рядок у `CMakeLists.txt` дописується так само:

```cmake
add_executable(ex05_pointers  exercises/ex05_pointers.cpp)
```

Ми беремо ту саму чергу повторення, що й в уроці 4, і робимо з нею те саме — але без жодного контейнера зі стандартної бібліотеки. Голі масиви, голі адреси. Не тому що так треба писати (не треба), а тому що `std::vector`, `std::string` і розумні вказівники з наступних уроків усередині влаштовані саме так, і без цього уроку вони назавжди лишаться магією.

```cpp
// exercises/ex05_pointers.cpp
// Черга повторення через голі вказівники — так, як це виглядає без контейнерів.
// Збери разом із проєктом: cmake --build build
// Запусти:                 ./build/ex05_pointers

#include <iostream>
#include <string>

// ===== Підвищує рівень слова за адресою — оригінал теж змінюється =====
void promoteLevel(int* pLevel) {
    *pLevel += 1;   // "*" тут означає "за адресою, яку зберігає pLevel"
    std::cout << "  [усередині функції] рівень став " << *pLevel << "\n";
}

// ===== Рядок передаємо за константним посиланням — без копіювання =====
int countVowels(const std::string& translit) {
    int count = 0;
    for (char c : translit) {
        if (c == 'a' || c == 'e' || c == 'i' || c == 'o' || c == 'u') ++count;
    }
    return count;
}

// ===== Повертає адресу першого невивченого слова, або nullptr =====
int* findFirstUnlearned(int* begin, int* end) {
    for (int* it = begin; it != end; ++it) {
        if (*it == 0) return it;   // знайшли — повертаємо адресу
    }
    return nullptr;                // усе вивчено — повертаємо "нікуди"
}

int main() {
    // ===== Частина 1: вказівник — це адреса =====
    int level = 3;
    int* pLevel = &level;   // &level = адреса змінної level

    std::cout << "рівень слова     = " << level << "\n";
    std::cout << "адреса рівня     = " << pLevel << "   <- у тебе буде інше число\n";
    std::cout << "рівень за адресою= " << *pLevel << "\n";

    promoteLevel(pLevel);
    std::cout << "після виклику level = " << level << "  <- змінився оригінал\n\n";

    // ===== Частина 2: nullptr =====
    int* pNothing = nullptr;
    if (pNothing == nullptr) {
        std::cout << "pNothing нікуди не вказує — чіпати його не можна\n";
    }
    // *pNothing = 5;   НІКОЛИ: це аварійне завершення програми
    std::cout << "\n";

    // ===== Частина 3: посилання — просто друге ім'я =====
    int& currentLevel = level;   // не копія і не вказівник
    currentLevel = 5;
    std::cout << "через друге ім'я level = " << level << "\n\n";

    // ===== Частина 4: const& — великий рядок без копіювання =====
    const std::string translit = "ahimsa";
    std::cout << "голосних у \"" << translit << "\": " << countVowels(translit) << "\n\n";

    // ===== Частина 5: словник як два голі масиви =====
    // Ті самі паралельні масиви з уроку 4, тільки без std::vector.
    const char* names[6] = { "dharma", "satya", "ahimsa", "karma", "yoga", "guru" };
    int levels[6]        = {        2,       1,        4,       3,      1,      5 };
    int known[6]         = {        1,       1,        0,       0,      1,      0 };

    int* p = levels;   // ім'я масиву саме перетворюється на адресу першого елемента
    std::cout << "рівень першого слова  = " << *p << "\n";
    std::cout << "рівень третього слова = " << *(p + 2) << "   <- зсув на 2 елементи\n";
    std::cout << "усі рівні через арифметику: ";
    for (int i = 0; i < 6; ++i) {
        std::cout << *(p + i) << " ";
    }
    std::cout << "\n\n";

    // ===== Частина 6: розмір масиву губиться при передачі =====
    std::cout << "sizeof(levels) = " << sizeof(levels) << "  (увесь масив)\n";
    std::cout << "sizeof(p)      = " << sizeof(p)      << "  (лише адреса)\n\n";

    // ===== Частина 7: що показати наступним =====
    int* next = findFirstUnlearned(known, known + 6);
    if (next != nullptr) {
        int index = static_cast<int>(next - known);   // різниця адрес = індекс
        std::cout << "наступним показуємо: " << names[index]
                  << "  (індекс " << index << ", рівень " << levels[index] << ")\n";
    } else {
        std::cout << "усе вивчено, показувати нічого\n";
    }

    return 0;
}
```

Вивід:

```
рівень слова     = 3
адреса рівня     = 000000F1EBCFFB20   <- у тебе буде інше число
рівень за адресою= 3
  [усередині функції] рівень став 4
після виклику level = 4  <- змінився оригінал

pNothing нікуди не вказує — чіпати його не можна

через друге ім'я level = 5

голосних у "ahimsa": 3

рівень першого слова  = 2
рівень третього слова = 4   <- зсув на 2 елементи
усі рівні через арифметику: 2 1 4 3 1 5

sizeof(levels) = 24  (увесь масив)
sizeof(p)      = 8  (лише адреса)

наступним показуємо: ahimsa  (індекс 2, рівень 4)
```

Другий рядок варто перевірити окремо: запусти програму двічі підряд. У мене вийшло `000000F1EBCFFB20`, а наступного разу — `00000083F45DFB90`. Адреса **змінюється при кожному запуску**, і це не збій. Операційна система навмисно розкидає пам'ять програми по випадкових місцях (механізм називається ASLR, address space layout randomization), щоб зловмиснику було важче вгадати, за якою адресою лежить потрібний йому шматок даних. Практичний висновок для тебе простий: конкретне число адреси не означає нічого й запам'ятовувати його немає сенсу. Значення має тільки те, чи вказівники рівні між собою і чи не `nullptr`.

Розберемо це рядок за рядком.

**`int* pLevel`** — оголошення вказівника. `int*` читається як «вказівник на int». Зірочка тут частина типу, а не оператор. Це як казати «масив рядків» — ти кажеш, який саме тип, а не «помножити».

**`&level`** — оператор «взяти адресу». У попередньому уроці ми зустрічали `&` у `const std::string&` і там він означав «посилання». У C++ `&` має кілька значень залежно від контексту. Це дратує перші два тижні, потім стає звичкою. Пам'ятай: коли `&` стоїть **перед іменем змінної** (`&level`) — це «адреса», коли **у типі** (`int& ref`) — це «посилання». Різні речі, схожа записка.

**`*pLevel`** — оператор «розіменування». «Іди за адресою, яку зберігає pLevel, і покажи, що там лежить». У функції `promoteLevel` рядок `*pLevel += 1` означає «за адресою, яку зберігає pLevel, збільш число на одиницю». Оскільки `pLevel` вказує на `level` із `main`, то й `level` після виклику дорівнює 4 — подивись на вивід. Це той самий будинок, побачений з двох різних боків: через вказівник і через ім'я.

Зверни увагу, що саме тут ховається головна практична причина існування вказівників. Функція `promoteLevel` не повертає нічого, але змінює змінну, яка живе в іншій функції. Без вказівника (чи посилання) це неможливо: параметри в C++ за замовчуванням копіюються, і функція, яка отримала копію рівня, підвищила б копію, а оригінал лишився б недоторканим.

**`nullptr`** — спеціальне значення, яке означає «вказівник, що нікуди не вказує». Спроба розіменувати `nullptr` — гарантований крах програми (або того гірше, в залежності від ОС). Це, як не дивно, добре: краще впасти одразу, ніж працювати з випадковими даними. Завжди перевіряй, чи не `nullptr` твій вказівник, перед тим як його розіменовувати. У новому коді C++ — тільки `nullptr`. Старий макрос `NULL` (розгортається в `0`) і досі зустрічається в легасі-коді, але не використовуй його в нових проектах.

**`int& currentLevel = level;`** — посилання. `currentLevel` — це **інше ім'я** того самого `level`. Не копія, не новий об'єкт, не вказівник з додатковим кроком розіменування — просто ще одне ім'я. Присвоїли `currentLevel = 5` — і `level` теж став 5, що видно у виводі. Це найпростіше для розуміння, якщо уявити, що в тебе є друг, якого всі кличуть двома іменами: «Остап» і «Бендер». Це той самий чоловік, просто різні клички.

**`const std::string& translit` у функції** — найчастіше застосування посилань. Без `&` ми б копіювали весь рядок при кожному виклику (навіть якщо він на 10 000 символів). З `&` — функція отримує «друге ім'я» рядка, без копіювання. `const` обіцяє, що функція його не змінить. Це шаблон, який використовується в 90% реального C++ коду. Запам'ятай: «велика штука для читання — передавай за `const&`».

**`int* p = levels`** — ім'я масиву автоматично перетворюється на вказівник на перший елемент. Це зроблено для зручності, але створює купу непорозумінь. Подивись на вивід: `sizeof(levels)` дає розмір усього масиву (6 × 4 = 24 байти), а `sizeof(p)` — розмір самої адреси (8 байтів), хоч обидва «вказують» на ті самі дані. Масив — це область пам'яті, вказівник — це адреса. Коли масив «перетворюється» на вказівник (зокрема, коли передається у функцію), він **втрачає інформацію про свій розмір назавжди**. Саме тому в `findFirstUnlearned` довелося передавати дві адреси — початок і кінець: інакше функція не мала б жодного способу дізнатися, де масив закінчується.

**`*(p + 2)`** — арифметика вказівників. Компілятор знає, що `p` вказує на `int`, тому `p + 2` зсувається не на 2 байти, а на 2 × `sizeof(int)` = 8 байтів. Це зручно, але саме тут народжуються класичні помилки: `*(p + 100)` «спрацює» — прочитає щось із чужої пам'яті, і ти дізнаєшся про баг через місяць, коли програма впаде в продакшні. У C++ немає автоматичної перевірки меж масиву. Це робить мову швидкою, але небезпечною.

**`next - known`** — відстань між двома вказівниками. Повертає індекс елемента (бо компілятор знає розмір `int`), і саме завдяки цьому ми змогли з адреси в масиві `known` дістати номер слова, а вже за номером — його назву з масиву `names` і рівень з масиву `levels`. Три паралельні масиви, один індекс. Працює це тільки коли обидва вказівники вказують на елементи **одного масиву**; віднімати вказівники з різних масивів — невизначена поведінка.

І ось тут варто зупинитися й подивитися на код чесно. Щоб відповісти на просте питання «яке слово показати наступним», нам довелося: тримати три масиви синхронними вручну, окремо пам'ятати, що їх по шість, передавати межі в функцію двома аргументами, дістати індекс відніманням адрес і тричі проіндексувати різні масиви. Кожен із цих кроків — місце, де можна помилитися й не отримати жодного попередження від компілятора. В уроці 8 ми складемо ці три масиви в одну структуру `Word`, і питання «яке слово наступне» перетвориться на один рядок. Але тепер ти знатимеш, що саме `std::vector<Word>` робить за тебе — і чому це не магія.

## Дикий, висячий і той, що витікає

Три класичні неприємності, і всі три легко уявити через той самий папірець з адресою з початку уроку. **Дикий вказівник** (wild pointer) — оголошений, але не ініціалізований:

```cpp
int* p;  // куди вказує? невідомо — там щось сміттєве з пам'яті
*p = 5;  // майже напевно крах, а іноді — щось гірше: тихе псування чужих даних
```

На відміну від `nullptr`, який падає передбачувано й одразу, дикий вказівник іноді «спрацьовує» — тому що сміттєва адреса випадково потрапила в область пам'яті, доступну для читання й запису. Програма не падає, а починає непомітно псувати щось інше, і баг спливе зовсім не там, де була справжня причина.

**Висячий вказівник** (dangling pointer) — вказував на щось справжнє, але це «щось» уже перестало існувати:

```cpp
int* dangerous() {
    int local = 42;
    return &local;  // пастка: local помирає разом із виходом із функції
}
```

`local` живе рівно до кінця функції — щойно вона завершується, ця пам'ять вважається вільною і може бути тут же перевикористана під що завгодно інше. Повернутий вказівник і далі містить цю адресу, але гарантії, що там усе ще лежить `42`, більше немає. Компілятор із увімкненими попередженнями зазвичай підсвічує це — не ігноруй такі попередження.

**Витік пам'яті** (memory leak) — коли пам'ять виділили вручну через `new`, а вказівник на неї загубили, так і не викликавши `delete`. Розберемо це по-справжньому в уроці 11.

## Міст до всього, що буде далі

**Увесь сучасний C++ побудований на вказівниках під капотом.** Коли ти пишеш `std::string name = "Остап";`, всередині `std::string` зберігає вказівник на ділянку пам'яті з символами. Коли ти пишеш `std::vector<int> v;` і додаєш елементи, `vector` зберігає вказівник на динамічно виділену пам'ять. Коли ти викликаєш метод класу, компілятор під капотом передає прихований параметр — `this` — який і є вказівником на поточний об'єкт. Коли використовується поліморфізм (віртуальні функції), об'єкт зберігає вказівник на таблицю віртуальних методів (vtable), і виклик методу — це «подивись у таблиці, яка функція відповідає цьому методу, і виклич її».

**Системне програмування без вказівників не існує.** Ядро Linux — це десять мільйонів рядків коду, де `*` зустрічається в кожному другому файлі. Драйвери пристроїв, мережеві протоколи, файлові системи — все це маніпуляції з адресами в пам'яті. Коли ти вчиш вказівники, ти вчиш не синтаксичну цукерку, а те, як влаштований комп'ютер насправді.

**Історична цитата**: Денніс Рітчі, творець C, одного разу сказав, що вказівники — це «головна причина, чому C такий потужний і такий небезпечний». Він мав рацію. У Java, де вказівників «немає» (є посилання, але без арифметики), щороку латають діри в sandbox. У C++ ти сам вирішуєш, наскільки глибоко лізти в пам'ять. Це і є сила, і є джерело всіх «segfault у понеділок вранці».

**Аналогія з навігатором**: адреса будинку у вказівнику — це як координати в навігаторі. Можна їхати за ними (розіменувати), можна зберегти в закладки (копія вказівника), можна видалити будинок, а координати залишаться (висячий вказівник — класична помилка). Арифметика вказівників — це як «поїхали на 2 квартали вперед». Все просто, поки не звернеш не туди.

## Куди це веде в сучасному C++

**Замість вказівників на окремі об'єкти** — розумні вказівники (у нас цілий урок 12), які самі стежать за часом життя:

```cpp
// Старий стиль
Word* w = new Word("धर्म");
delete w;  // забув = витік пам'яті

// Новий стиль
auto w = std::make_unique<Word>("धर्म");
// delete не потрібен — unique_ptr сам прибере
```

**Замість масивів у стилі C** — `std::vector` або `std::array`:

```cpp
// Старий стиль
int numbers[5] = {1, 2, 3, 4, 5};
// sizeof(numbers) = 20 байт, але передаси в функцію — sizeof = 8 байт (покажчик)
// Довжину треба передавати окремо

// Новий стиль
std::vector<int> numbers = {1, 2, 3, 4, 5};
// sizeof(numbers) = 24 байт (але це контейнер, що вміє зростати)
// Довжина доступна як numbers.size()
```

**Замість `int* p = &x;`** — посилання, якщо об'єкт точно існує і не зміниться:

```cpp
void increment(int& x) { ++x; }   // x точно існує
int* maybeIncrement(int* p) {
    if (!p) return nullptr;       // p може бути nullptr
    ++(*p);
    return p;
}
```
