# ADR 0009 — файли за інтерфейсом FileStorage, на диску під випадковим ключем

**Статус:** прийнято, 2026-10-19.

## Контекст

Є два види файлів: матеріали уроків і файли домашніх робіт. Вони завантажуються користувачами, тому
потрібні обмеження за розміром і типом, захист від обходу шляхів і від виконання завантаженого вмісту.
Місце зберігання (локальний диск) має бути замінюваним.

## Розглянуті варіанти

1. **Файл у БД (`bytea`).** Транзакційно, але роздуває базу й резервні копії.
2. **Одразу S3.** Масштабується, але потребує зовнішнього сервісу й ключів для захисту проєкту.
3. **Диск за інтерфейсом `FileStorage { save, open, remove }`.** Просто зараз, замінюється пізніше.

## Рішення

Файл пишеться на диск у volume під випадковим UUID без розширення. Ім'я від клієнта зберігається окремо
в БД після очищення (`cleanName`). Ключ перевіряється регулярним виразом (`KEY_PATTERN`) перед читанням.
Завантаження через `express.raw` до 10 МБ, дозволено 27 розширень. Віддається як
`application/octet-stream` із `nosniff` і `attachment`.

## Наслідки

- (+) Обхід шляхів неможливий: ім'я файлу на диску ніколи не береться від користувача.
- (+) Заміна на S3 зачіпає один файл.
- (−) Немає антивірусної перевірки.
- (−) Локальний диск не підходить для кількох серверів, потрібен спільний volume або S3.

## Умова перегляду

Перехід на кілька екземплярів API або на публічний хостинг: реалізуємо `FileStorage` для S3.
