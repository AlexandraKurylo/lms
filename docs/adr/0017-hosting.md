# ADR 0017 — Хостинг: Render, один Docker-сервіс (API віддає клієнт) і PostgreSQL

**Статус:** прийнято, 2026-10-29.

## Контекст

Методичка вимагає публічне посилання з дійсним сертифікатом HTTPS. Локально застосунок складається з трьох
контейнерів (ADR 0001): PostgreSQL, API і nginx, який віддає клієнт і проксує `/api`. Завантажені файли API
зберігає на диску (ADR 0009).

Спершу обрано Railway: постійні томи, база як сервіс, розгортання з GitHub. Проте 21 жовтня 2026 року в Railway
стався інцидент безпеки, і реєстрація нових акаунтів там призупинена на невизначений час. Окрім того, платформа
порадила змінити всі збережені на ній секрети. Тому проєкт розгортається на іншому хостингу.

## Розглянуті варіанти

1. **Railway.** Технічно найзручніший, але нові акаунти не створюються, а довіра до зберігання секретів знижена.
2. **Fly.io.** Безкоштовного тарифу для нових акаунтів немає, потрібна картка; кероване Postgres дороге.
3. **Render, безкоштовний тариф.** Є HTTPS, розгортання з GitHub і Docker, безкоштовний PostgreSQL на 30 днів, картка не
   обов'язкова. Недоліки: файлова система тимчасова (файли зникають при перезапуску), сервіс засинає після
   15 хвилин без запитів і прокидається близько хвилини, 750 безкоштовних годин на місяць на весь акаунт.
   Безкоштовні сервіси не приймають запитів із приватної мережі, тому окремий nginx не зміг би дістатися до API.

## Рішення

Варіант 3 в одному сервісі. Єдиний Docker-образ збирає клієнт і сервер, а API віддає зібрані файли клієнта
(`STATIC_DIR`) і відповідає на `/api`. Це дає один origin без CORS і лише один сервіс із безкоштовних годин. Для
`docker compose` нічого не змінюється: там клієнт, як і раніше, віддає nginx. Конфігурація хостингу лежить у
`render.yaml` (Blueprint): сервіс `lms` і база `lms-db`. Порядок розгортання: [docs/deploy.md](../deploy.md).

## Наслідки

- (+) Безкоштовно, без картки; усе розгортання описано в `render.yaml`.
- (+) Один origin: cookie без налаштування CORS, `COOKIE_SECURE=true` за HTTPS.
- (+) Зміни з `main` розгортаються автоматично.
- (−) Файли користувачів на хостингу не зберігаються між перезапусками й розгортаннями. Запис про файл у базі
  лишається, тож відкриття такого файла повертає помилку. Для демонстрації файл завантажують безпосередньо перед
  показом.
- (−) Перший запит після простою триває близько хвилини.
- (−) Безкоштовна база видаляється через 30 днів після створення; резервних копій на цьому тарифі немає.
- (−) Сервіс і клієнт розгортаються разом: зміна лише клієнта теж перезбирає API.

## Умова перегляду

Якщо потрібні постійні файли, переходимо на платний тариф Render із диском або на VPS із `docker compose`
(конфігурація вже готова).
