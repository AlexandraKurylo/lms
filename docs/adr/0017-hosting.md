# ADR 0017 — Хостинг: Railway (API, веб-сервер і PostgreSQL окремими сервісами)

**Статус:** прийнято, 2026-10-29.

## Контекст

Методичка вимагає публічне посилання з дійсним сертифікатом HTTPS. Застосунок складається з трьох частин (ADR 0001):
PostgreSQL, API (Express) і веб-сервер nginx зі зібраним клієнтом, який проксує `/api` на API. API зберігає
завантажені файли на диску (ADR 0009), тому хостинг має давати постійний диск. Для API потрібне керування
міграціями: контейнер сам виконує `prisma migrate deploy` під час старту.

## Розглянуті варіанти

1. **Render (безкоштовний тариф).** Є HTTPS і розгортання з GitHub, картка не обов'язкова. Але на безкоштовному
   тарифі немає постійних дисків (файли зникають при перезапуску), сервіс «засинає» через 15 хвилин без запитів
   і прокидається близько хвилини, а безкоштовна база видаляється через 30 днів і не підтримує резервні копії.
2. **Fly.io.** Нові акаунти не мають безкоштовного тарифу: після короткого пробного періоду потрібна картка.
   Кероване Postgres значно дорожче за решту варіантів.
3. **Railway.** Пробний період 30 днів із разовим кредитом $5, потім тариф Hobby ($5 на місяць). Є PostgreSQL як
   сервіс, постійні томи, розгортання з GitHub за Dockerfile, домени з HTTPS і внутрішня мережа між сервісами.

Умови хостингів змінюються, тому значення перевірено за документацією на 2026-10-29.

## Рішення

Варіант 3. Проєкт складається з трьох сервісів: `Postgres` (шаблон Railway), `api` (каталог `server`, Dockerfile) і
`web` (каталог `client`, Dockerfile). Публічний домен має лише `web`, API доступний тільки через внутрішню мережу
за адресою `api.railway.internal:4000`. Файли користувачів лежать на томі, змонтованому в `/data/uploads`.

Щоб nginx працював і в `docker compose`, і на хостингу, його конфігурація стала шаблоном: порт задає змінна `PORT`,
адресу API задає `API_UPSTREAM` (за замовчуванням `api:4000`, як у `docker-compose.yml`).

Зміни з `main` розгортаються автоматично. Покрокова інструкція: [docs/deploy.md](../deploy.md).

## Наслідки

- (+) Один домен для клієнта й API: cookie без налаштування CORS, `COOKIE_SECURE=true` за HTTPS.
- (+) Файли переживають перезапуски й нові розгортання, бо лежать на томі.
- (+) Локальний `docker compose` працює без змін.
- (−) Платний після пробного періоду; без поповнення кредитів сервіси зупиняються, а томи видаляються через 30 днів.
- (−) Сервіс `web` не стартує, поки не розв'язується адреса `api.railway.internal`; при першому розгортанні
  контейнер може один-два рази перезапуститися, поки `api` не запуститься.
- (−) Привʼязка до конкретного хостингу: переніс на інший потребує повторного налаштування змінних і тому.

## Умова перегляду

Якщо вартість або умови Railway стануть неприйнятними, переходимо на VPS із `docker compose` (конфігурація вже
готова) або на інший хостинг із постійними дисками.
