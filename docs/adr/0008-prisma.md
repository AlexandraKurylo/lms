# ADR 0008 — Prisma для доступу до PostgreSQL і міграцій

**Статус:** прийнято, 2026-10-18.

## Контекст

До цього кроку сервер працював із базою напряму через `pg`: SQL у репозиторіях писався вручну, а
міграції накочував власний скрипт. Вимога курсу — використовувати Prisma. Водночас схема LMS має
частину обмежень, яких Prisma не описує: часткові унікальні індекси (один безкоштовний вступний урок,
один активний запис на курс), `DEFERRABLE`-обмеження позицій уроків, `CHECK`-и та індекс `lower(email)`.

## Розглянуті варіанти

1. **Лишити `pg` і ручний SQL.** Максимальний контроль, але немає типобезпечних запитів і
   стандартного інструмента міграцій; не відповідає вимозі курсу.
2. **Prisma повністю, схема лише з `schema.prisma`.** Найменше коду, але втрачаємо часткові індекси
   та обмеження: гарантії конкурентного запису на потік довелося б перевіряти лише в коді.
3. **Prisma Client + Prisma Migrate, а обмеження, яких Prisma не вміє, додаємо вручну в SQL міграції.**

## Рішення

Обрано варіант 3. `prisma/schema.prisma` описує моделі, зв'язки та звичайні індекси. Початкова схема
лежить у `prisma/migrations/20261017000000_init/migration.sql`: це та сама SQL-схема, що була раніше,
із коментарем, що саме Prisma в ній не бачить. Міграції створюються командою `prisma migrate dev`
(для розробки) і застосовуються `prisma migrate deploy` (на сервері). `prisma db push` не
використовується: він не лишає історії змін.

Зафіксовано Prisma 6 (`prisma@6`, `@prisma/client@6`): нова мажорна версія має інший CLI й формат
конфігурації, а код і схема написані під шосту.

Репозиторії (`auth.repo.ts`, `catalog.repo.ts`) переписані на Prisma Client. Сервіси, маршрути й
контракт API не змінилися. Транзакції виконуються через `prisma.$transaction`, а блокування рядка
потоку на кроках запису буде через `$queryRaw` із `SELECT … FOR UPDATE`.

## Наслідки

- Плюси: типізовані запити, одна команда відтворює базу (`npm run db:reset`), історія змін схеми.
- Мінуси: частина гарантій живе в SQL-файлі міграції, тому при зміні моделі її треба правити вручну;
  Prisma Client треба генерувати (`prisma generate`) після install і зміни схеми.
- База, створена старим скриптом, розходиться з історією Prisma, тому під час переходу її один раз
  скидають командою `npm run db:reset`, а дані відновлює сид (`npm run db:seed`).
- Кількість запитів на сторінку каталогу не повинна залежати від розміру сторінки; це перевіримо за
  журналом запитів (`PRISMA_LOG=query`) на кроці 21.

## Умова перегляду

Якщо обмежень, які доводиться тримати вручну в SQL, стане більше, ніж описаних у схемі, або Prisma
почне заважати складним запитам, варто повернутися до явного SQL для проблемних місць.
