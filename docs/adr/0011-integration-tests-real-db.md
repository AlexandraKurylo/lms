# ADR 0011 — інтеграційні тести на справжній PostgreSQL

**Статус:** прийнято, 2026-10-20.

## Контекст

Найважливіші гарантії проєкту живуть у базі: `SELECT … FOR UPDATE`, частковий унікальний індекс на місце,
CHECK-обмеження, складений зовнішній ключ. Тест із підміненою БД їх не перевірить, а саме на них
тримається коректність конкурентного запису.

## Розглянуті варіанти

1. **Мок репозиторіїв або SQLite у памʼяті.** Швидко, але поведінка блокувань та індексів інша.
2. **Окрема база `<db>_test` у тому ж PostgreSQL 16.** Повільніше, але перевіряє реальні гарантії.

## Рішення

Тести (vitest + supertest) піднімають застосунок через `startKit()` на окремій базі `<db>_test`.
Перед кожним тестом виконується `TRUNCATE users RESTART IDENTITY CASCADE`. Файли тестів виконуються
послідовно (`fileParallelism: false`), бо ділять одну базу.

## Наслідки

- (+) Тест на 50 паралельних запитів на 10 місць доводить, що блокування працює насправді.
- (+) Помилки в SQL і міграціях ловляться до продакшену.
- (−) Потрібен запущений PostgreSQL, повний прогін повільніший за юніт-тести.
- (−) Послідовне виконання файлів збільшує час прогону.

## Умова перегляду

Якщо прогін стане занадто довгим, виділяємо окрему базу на кожного воркера й вмикаємо паралельність.
