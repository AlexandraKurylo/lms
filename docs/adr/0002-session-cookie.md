# ADR 0002 — Сесія в httpOnly cookie замість токена в localStorage

**Статус:** прийнято, 2026-10-17.

## Контекст

Сайт (React) і сервер працюють на одному домені: під час розробки через проксі Vite,
у production через reverse proxy. Користувач має залишатися авторизованим між запитами.
Токен входу не повинен потрапити до зловмисника, навіть якщо на сторінці раптом
з'явиться шкідливий скрипт (XSS). Роль користувача (студент, викладач, адміністратор)
сервер перевіряє на кожному запиті.

## Розглянуті варіанти

1. **JWT у `localStorage` + заголовок `Authorization: Bearer`.** Просто для фронтенду
   і підходить для мобільних застосунків. Але будь-який скрипт на сторінці може прочитати
   `localStorage`, тож при XSS токен буде вкрадено. Крім того, вийти з системи на сервері
   неможливо, поки токен не закінчиться.
2. **JWT в httpOnly cookie (`SameSite=Lax`, `Secure` у production).** Скрипт сторінки
   не бачить такий cookie, а браузер сам додає його до запитів. Потрібно подумати про
   CSRF, але `SameSite=Lax` не дає браузеру надсилати cookie з чужих сайтів у POST-запитах,
   а наш API приймає лише JSON.
3. **Серверні сесії в таблиці (у cookie лише id сесії).** Сесію найлегше скасувати, але
   кожен запит читає базу, і потрібна додаткова таблиця.

## Рішення

Беремо підписаний JWT (алгоритм HS256, термін 7 днів) у httpOnly cookie `lms_session`.
Головний недолік JWT у тому, що його не можна скасувати. Щоб це пом'якшити, на кожному
запиті ми заново читаємо користувача з бази: якщо акаунт видалили або змінили роль,
це діє одразу, а не через 7 днів.

## Наслідки

- (+) Скрипт на сторінці не може прочитати токен.
- (+) Фронтенду не треба самому зберігати токен: достатньо звертатися до API з
  `credentials: 'same-origin'`.
- (−) На кожен запит із входом додається один запит до бази (за `id`, індекс є).
- (−) Кнопки «вийти з усіх пристроїв» немає: токен діє до кінця терміну.
- (−) Якщо API колись переїде на інший домен, доведеться налаштовувати CORS і
  `SameSite=None; Secure`.

## Умова перегляду

Якщо з'являться мобільні клієнти, API на окремому домені або вимога миттєво
завершувати всі сесії, перейдемо на серверні сесії (варіант 3) або на короткоживучий
токен із refresh-токеном.
