# ADR 0002 — Сесія в httpOnly cookie замість токена в localStorage

**Статус:** прийнято, 2026-10-17. Частково замінено [ADR 0012](0012-refresh-rotation.md): термін життя сесії й оновлення (httpOnly cookie лишається).

## Контекст

Вебзастосунок (React) і API живуть на одному домені: у розробці через проксі Vite, у production — через
reverse proxy. Потрібно, щоб користувач залишався залогіненим між запитами, а токен не можна було
вкрасти скриптом, якщо на сторінці раптом з'явиться XSS. Ролі (студент / викладач / адміністратор)
перевіряються на сервері на кожному запиті.

## Розглянуті варіанти

1. **JWT у `localStorage` + заголовок `Authorization: Bearer`.** Просто для клієнта, зручно для
   мобільних застосунків. Але будь-який скрипт на сторінці читає `localStorage`, тож XSS означає
   викрадений токен. Вихід із системи на сервері неможливий до закінчення терміну токена.
2. **JWT в httpOnly cookie (`SameSite=Lax`, `Secure` у production).** Скрипт токена не бачить, браузер
   додає cookie сам. Потрібно окремо думати про CSRF, але `SameSite=Lax` не надсилає cookie з
   міжсайтових POST-запитів, а API приймає лише JSON.
3. **Серверні сесії в таблиці (session id у cookie).** Найлегше відкликати сесію, але кожен запит —
   додаткове читання з бази й ще одна таблиця для підтримки.

## Рішення

Підписаний JWT (HS256, 7 днів) у httpOnly cookie `lms_session`. Щоб компенсувати головний недолік
JWT, на кожному запиті користувача перечитуємо з бази: видалений акаунт чи змінена роль діють одразу,
а не після закінчення токена.

## Наслідки

- (+) XSS не може прочитати токен; клієнт не керує ним вручну.
- (+) Фронтенд просто викликає API з `credentials: 'same-origin'`, окремої логіки зберігання немає.
- (−) Один додатковий запит до бази на автентифікований запит (потрібен індекс по `id`, він є).
- (−) Окремий «вихід з усіх пристроїв» не підтримується: токен дійсний до закінчення терміну.
- (−) Якщо API колись переїде на інший домен, доведеться налаштовувати CORS і `SameSite=None; Secure`.

## Умова перегляду

Якщо з'являться мобільні клієнти, окремий домен API або вимога миттєво завершувати всі сесії,
переходимо на серверні сесії (варіант 3) або короткоживучий токен із refresh-токеном.
