# Розгортання на Render

Застосунок розгорнуто як один Docker-сервіс `lms` (API разом із зібраним клієнтом) і базу даних `lms-db` на Render.
Вибір хостингу обґрунтовано в [ADR 0017](adr/0017-hosting.md). Конфігурацію збережено у `render.yaml` у корені
репозиторію, тому все налаштування відтворюється з коду. Публічна адреса: https://lms-p949.onrender.com.

## Налаштування розгортання

1. Виконано реєстрацію на [render.com](https://render.com) через акаунт GitHub.
2. Створено **New → Blueprint**, обрано репозиторій `AlexandraKurylo/lms` і гілку `main`. Render прочитав
   `render.yaml` і запропонував створити сервіс `lms` та базу `lms-db`, обидва на тарифі Free.
3. Підтверджено кнопкою **Apply**. Змінні `DATABASE_URL` (береться з бази), `JWT_SECRET` (генерується Render) і
   `COOKIE_SECURE` задаються Blueprint автоматично, тому вручну їх вводити не довелося.
4. Розгортання завершилося після того, як база отримала статус **Available**, а в логах сервісу `lms` з'явився рядок
   `api listening`. Перша збірка тривала кілька хвилин.
5. Отримано публічне посилання виду `https://lms-xxxx.onrender.com`. Сертифікат HTTPS видається Render автоматично.

Запасний варіант на випадок, якщо Blueprint не спрацює, передбачає ручне налаштування: **New → PostgreSQL**
(Free, версія 16), потім **New → Web Service** з репозиторію з параметрами **Language: Docker**,
**Instance Type: Free**, **Health Check Path:** `/api/ready` і змінними `DATABASE_URL` (внутрішній URL бази),
`JWT_SECRET` (щонайменше 32 символи), `COOKIE_SECURE=true`.

## Завантаження демо-даних

Таблиці створюються самі під час старту сервісу командою `prisma migrate deploy`, тому окремий запуск міграцій не
потрібен. Демо-дані завантажено один раз з локального комп'ютера: у базі `lms-db` на вкладці **Connections**
скопійовано **External Database URL**, у кінець дописано `?sslmode=require`, після чого в каталозі `server`
виконано (PowerShell):

```powershell
$env:DATABASE_URL = "<зовнішній URL бази>?sslmode=require"
npm run db:seed
Remove-Item Env:DATABASE_URL
```

Сид створив 40 курсів, 80 потоків, 500 уроків, 200 студентів і 800 записів. Запускався він лише раз, оскільки
очищує таблиці перед заповненням. Демо-акаунти описано в README.

## Оновлення

Кожне злиття в `main` запускає нове розгортання (у `render.yaml` задано `autoDeployTrigger: commit`). Міграції
застосовуються автоматично під час старту сервісу, тож ручних кроків після злиття немає.

## Перевірка розгортання

1. Відкрито посилання: перший запит після простою тривав близько хвилини, після чого завантажився каталог курсів.
2. Виконано вхід як `student001@example.com` / `Demo12345!`, відкрито курс і виконано запис на потік.
3. Підтверджено захищене з'єднання: у браузері відображається замок, адреса починається з `https://`.
4. Сторінку на адресі `/courses/1` оновлено: вона відкрилася без помилки, отже клієнтські маршрути віддаються
   сервером коректно.

## Виявлені обмеження

- **Файли користувачів не зберігаються між перезапусками й розгортаннями.** Тому файл матеріалу чи домашньої роботи
  потрібно завантажувати вже на розгорнутому сайті безпосередньо перед показом. Файли, завантажені раніше, можуть не
  відкритися.
- Сервіс засинає через 15 хвилин без запитів, і перший запит після цього триває близько хвилини. Тому перед показом
  сайт відкривається заздалегідь.
- Безкоштовна база видаляється через 30 днів після створення і не має резервних копій. Копію можна зробити локально:
  `BACKUP_MODE=local` і зовнішній URL у `DATABASE_URL` (потрібен клієнт PostgreSQL 16), див. [backup.md](backup.md).
