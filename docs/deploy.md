# Розгортання на Railway

Застосунок працює як три сервіси одного проєкту Railway: `Postgres`, `api` і `web`. Рішення обґрунтовано в
[ADR 0017](adr/0017-hosting.md).

## Одноразове налаштування

1. Увійдіть на [railway.com](https://railway.com) через GitHub і запустіть пробний період. Щоб відкрити повний
   доступ до мережі, підтвердьте GitHub-акаунт.
2. **New Project → Deploy PostgreSQL.** З'явиться сервіс `Postgres`.
3. **New → GitHub Repo →** `AlexandraKurylo/lms`. У налаштуваннях сервісу:
   - **Settings → Source → Root Directory:** `server`; назва сервісу `api`;
   - **Variables:**

     | Змінна               | Значення                                                         |
     | -------------------- | ---------------------------------------------------------------- |
     | `DATABASE_URL`       | `${{Postgres.DATABASE_URL}}`                                     |
     | `JWT_SECRET`         | випадковий рядок із щонайменше 32 символів                       |
     | `COOKIE_SECURE`      | `true`                                                           |
     | `API_PORT`           | `4000`                                                           |
     | `RAILWAY_RUN_UID`    | `0` (щоб API міг писати у змонтований том)                       |

   - **Volumes → Add Volume:** шлях монтування `/data/uploads`;
   - публічний домен для `api` не створюйте.
4. **New → GitHub Repo →** той самий репозиторій. У налаштуваннях:
   - **Root Directory:** `client`; назва сервісу `web`;
   - **Variables:** `API_UPSTREAM` = `api.railway.internal:4000`, `PORT` = `80`;
   - **Networking → Generate Domain** з портом `80`. Це і є публічне посилання з HTTPS.
5. Дочекайтеся зеленого розгортання `api` (у логах `api listening`), потім `web`.

## Демо-дані

Таблиці створюються самі під час старту `api` (`prisma migrate deploy`). Дані завантажуються один раз з вашого
комп'ютера. У сервісі `Postgres` на вкладці **Connect** скопіюйте **Public Network** URL і в каталозі `server`
виконайте (PowerShell):

```powershell
$env:DATABASE_URL = "<публічний URL бази>"
npm run db:seed
Remove-Item Env:DATABASE_URL
```

Сид створює 40 курсів, 80 потоків, 500 уроків, 200 студентів і 800 записів. Не запускайте його вдруге: він очищує
таблиці. Демо-акаунти описано в README.

## Оновлення

Кожне злиття в `main` запускає нове розгортання `api` і `web`. Увімкніть **Wait for CI** у налаштуваннях сервісів, щоб
розгортання починалося лише після зеленого CI. Міграції застосовуються автоматично під час старту `api`.

## Перевірка після розгортання

1. Відкрийте посилання: має завантажитися каталог курсів.
2. Увійдіть як `student001@example.com` / `Demo12345!`, відкрийте курс і запишіться на потік.
3. Увійдіть як `teacher01@example.com`, додайте файл до уроку, перезапустіть `api` (**Restart**) і перевірте, що файл
   відкривається: так перевіряється том.
4. Перевірте HTTPS: у браузері має бути замок, адреса починається з `https://`.

## Обмеження

- Після закінчення пробного періоду сервіси зупиняються, якщо немає оплаченого тарифу; томи видаляються через 30 днів.
- Резервні копії розгорнутої бази: `BACKUP_MODE=local` і публічний URL у `DATABASE_URL` (потрібен клієнт PostgreSQL 16
  на вашому комп'ютері), див. [backup.md](backup.md). Файли на томі цією командою не копіюються.
